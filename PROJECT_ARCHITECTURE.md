## System Overview

**Smart Pantry Order System** is a full-stack web application for managing food orders in a corporate pantry environment. It supports three user roles:
- **Users**: Place orders for food/beverages from their conference rooms
- **Pantry Staff**: View and process pending orders in real-time
- **Admins**: Monitor analytics, manage users, and view comprehensive order data

### Key Features
- Role-based access control (User, Pantry, Admin)
- Real-time order updates via polling
- Location-based ordering (5 conference rooms)
- Beautiful animated UI with Unsplash backgrounds
- Order tracking and history
- Analytics dashboard with charts
- JWT-based authentication

### Core Components

#### 1. **Database Manager** (`database.py`)
```python
class Database:
    - Connection pooling (1-10 connections)
    - Context manager for transactions
    - Query execution with RealDictCursor

class Table:
    - Query builder (select, insert, update, delete)
    - Chainable filters (eq, neq, gt, lt, order, limit)
    - Returns dict format: {"data": [...], "count": N}
```

**Key Feature**: Built custom query builder to mimic Supabase SDK interface for easy migration.

#### 2. **Authentication** (`auth.py`)
```python
- verify_password(plain, hashed) -> bool
  - PBKDF2-HMAC-SHA256 verification
  - Constant-time comparison (secrets.compare_digest)

- get_password_hash(password) -> str
  - 100,000 iterations (OWASP recommended)
  - 32-byte random salt
  - Format: pbkdf2_sha256$100000$<salt_b64>$<hash_b64>

- create_access_token(data, expires_delta) -> str
  - JWT token creation with HS256 algorithm

- get_current_user(token) -> dict
  - JWT token validation
  - Returns: {id, username, role}
```

#### 3. **Models** (`models.py`)
- **Enums**: UserRole, OrderStatus, Location
- **Request Models**: LoginRequest, OrderCreate, OrderUpdate
- **Response Models**: UserResponse, OrderResponse, MenuItemResponse
- **Validation**: Pydantic v2 for automatic validation

#### 4. **CORS Configuration**
```python
allow_origins=["*"]          # All origins (for development)
allow_credentials=False      # Required when origins=*
allow_methods=["*"]
allow_headers=["*"]
```

## Database Schema

### Tables

#### **users**
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role user_role NOT NULL DEFAULT 'user',  -- ENUM: user, pantry, admin
    created_at TIMESTAMPTZ DEFAULT NOW(),

Indexes:
```

#### **orders**
```sql
CREATE TABLE orders (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    items JSONB NOT NULL,              -- Array of {item_id, name, category, quantity}

    status order_status NOT NULL DEFAULT 'pending',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

Indexes:
  - idx_orders_user_id ON user_id
  - idx_orders_status ON status
  - idx_orders_created_at ON created_at DESC
  - idx_orders_location ON location
```

## Authentication & Security

### Authentication Flow

```
1. User Login
   ├─> Frontend: POST /auth/login {username, password}
   ├─> Backend: Verify password with PBKDF2
   ├─> Backend: Generate JWT token (24h expiry)
   └─> Frontend: Store token + user in localStorage

2. Authenticated Request
   ├─> Frontend: Add "Authorization: Bearer <token>" header
   ├─> Backend: Verify JWT signature & expiry
   ├─> Backend: Extract user data from token
   └─> Backend: Check role-based permissions

3. Token Expiry
   ├─> Backend: Returns 401 Unauthorized
   └─> Frontend: Clear localStorage, redirect to /login
```

### JWT Token Structure
```json
{
  "sub": "user_id",
  "username": "john_doe",
  "role": "user",
  "exp": 1234567890
}
```

### Password Security
- **Algorithm**: PBKDF2-HMAC-SHA256
- **Iterations**: 100,000 (OWASP recommended minimum)
- **Salt**: 32 bytes (256 bits) random
- **Comparison**: Constant-time to prevent timing attacks

### Role-Based Access Control

| Endpoint | User | Pantry | Admin |
|----------|------|--------|-------|
| POST /orders/create | ✅ | ❌ | ❌ |
| GET /orders/ | Own orders | All orders | All orders |
| GET /orders/pending | ❌ | ✅ | ✅ |
| PUT /orders/{id}/status | ❌ | ✅ | ✅ |
| GET /admin/* | ❌ | ❌ | ✅ |
| GET /menu/* | ✅ | ✅ | ✅ |

**Implementation**:
```python
# Decorator for role checking
def require_pantry(current_user = Depends(get_current_user)):
    if current_user["role"] not in ["pantry", "admin"]:
        raise HTTPException(403, "Pantry or admin access required")
    return current_user
```

## Real-time Updates

### Polling Strategy

The application uses **HTTP polling** instead of WebSockets for simplicity:

#### **Pantry Dashboard** (Near Real-time)
```typescript
// Poll every 2 seconds
useEffect(() => {
  const interval = setInterval(async () => {
    const orders = await api.getPendingOrders()
    setOrders([...orders])  // Force re-render with new array reference
  }, 2000)
  return () => clearInterval(interval)
}, [])
```

**Endpoint**: `GET /orders/pending`
- Returns: All orders with status='pending'
- Includes: Username join from users table
- Order: created_at ASC (oldest first)

#### **Admin Dashboard** (Periodic Refresh)
```typescript
// Poll every 10 minutes
useEffect(() => {
  const interval = setInterval(async () => {
    const [analytics, orders, users] = await Promise.all([
      api.getAnalytics(),
      api.getAllOrders(),
      api.getAllUsers()
    ])
    setAnalytics({...analytics})  // Force re-render
    setOrders([...orders])
    setUsers([...users])
  }, 600000)  // 10 minutes
  return () => clearInterval(interval)
}, [])
```

**Why Polling?**
- ✅ Simpler implementation (no WebSocket server)
- ✅ Works with standard HTTP/REST
- ✅ No connection management needed
- ✅ 2-second delay acceptable for pantry use case
- ❌ More server requests (but manageable with few users)

## Current Issues & Solutions

### ⚠️ Issue #1: Orders Not Showing Up

**Problem**: Orders created by users don't appear in pantry/admin dashboards.

**Root Cause**: Row Level Security (RLS) is enabled on Supabase database. RLS policies use `auth.uid()` which only works with Supabase's built-in authentication. Since we're using JWT-based auth, RLS blocks all operations.

**Evidence**:
```sql
-- RLS Policy (BLOCKING ACCESS)
CREATE POLICY "Users can create orders" ON orders
    FOR INSERT WITH CHECK (user_id::text = auth.uid()::text);
    -- ❌ auth.uid() returns NULL with direct PostgreSQL connection
```

**Solution**: Disable RLS on Supabase

**Option A - Via Supabase Dashboard** (RECOMMENDED):
1. Go to: https://app.supabase.com/project/uywfinwvdatmbmatdsjb
2. SQL Editor → Run `database/disable_rls.sql`
3. Restart backend server

**Option B - Switch to Local PostgreSQL**:
```bash
./database/setup_local_db.sh
# Update DATABASE_URL in backend/.env
DATABASE_URL=postgresql://postgres:password123@localhost:5432/smart_pantry
```

**Files Created**:
- `database/FIX_RLS_ISSUE.md` - Detailed fix documentation
- `database/disable_rls.sql` - SQL script to disable RLS
- `database/disable_rls_supabase.py` - Python automation script
- `database/schema_local.sql` - Local DB schema (no RLS)
- `database/setup_local_db.sh` - Local DB setup script

### ⚠️ Issue #2: Database Configuration Confusion

**Problem**: User thinks they're using local PostgreSQL, but `.env` still points to Supabase.

**Current State**:
```bash
# This is STILL SUPABASE CLOUD, not local PostgreSQL!
DATABASE_URL=postgresql://postgres:Guddi#2019@db.uywfinwvdatmbmatdsjb.supabase.co:5432/postgres
                                         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                         This is Supabase's cloud server
```

**To Truly Use Local PostgreSQL**:
1. Install PostgreSQL locally
2. Run `./database/setup_local_db.sh`
3. Update `DATABASE_URL` to `postgresql://postgres:password123@localhost:5432/smart_pantry`
4. Run migrations

## Performance Considerations

### Backend
- **Connection Pooling**: 1-10 PostgreSQL connections
- **Query Optimization**: Indexed columns (status, user_id, created_at)
- **Transaction Management**: Auto-commit on success, rollback on error

### Frontend
- **Code Splitting**: Next.js automatic per-route
- **Image Optimization**: Next.js Image component (not used for Unsplash CDN)
- **State Updates**: Force re-renders with spread operator `[...data]`
- **Polling Throttle**: 2s minimum interval to avoid overload

### Database
- **Indexes**: On frequently queried columns
- **JSONB**: Efficient storage for order items
- **Timestamps**: Automatic via triggers
